## Training notes
- Identity prompt format (`--sft-tokenizer-prompt-format identity`, SFTTokenizer, sc14 tokenizer), `--seq-length 524288`, MBS 1, GBS 32 (table above). The receipt's `selected_trajectories` (= samples) and `selection_sha256` must be adapted in a sbatch that hard-codes them (as for v1 - v3).
- Packed samples stay independent only with the THD packing path: PP = 1, or PP = 2 with MTP on the last stage (other pipeline layouts give some ranks `cu_seqlens = None`); CP <= 16 (per-sample padding to 2 x CP = 32 is what the ceil32 row budget assumes). The AGA SFT-v3 GB300 setup (TP4 CP16 EP32 PP1, MTP off) satisfies both.
- This corpus is the RAW format (like SFT-v3 itself). The AGA v3 run trains on an empty-think-prefix transform of v3; an etp variant of this corpus is a separate follow-up and must keep `assistant_token_counts` consistent.
- Options not built (DESIGN): OpenCode's summary-writing calls as a separate sample type (loss on the summary only), task-subagent sessions, the 2 hosted gomacro tasks.
