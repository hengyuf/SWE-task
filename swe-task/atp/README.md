# hengyuf's ATP app (DeepSWE campaign code)

hengyuf-owned copy of Baihe's `agent-teacher-pipelines` (ATP) DeepSWE app, with the same layout so that ATP's
scripts run unchanged where possible. It lets the swe-task synthetic-task pipeline run student/teacher probes on
Harbor DeepSWE tasks without any of Baihe's private files. One campaign can mix a **local** student (alias
`sc14`, served by hengyuf's vLLM workers behind `S/student` router) with **hosted** teachers/judges (`kimi`, `glm`
on `https://inference-api.nvidia.com/v1`). Contract: `../docs/port-contract.md`.

  `/lustre/fsw/portfolios/nemotron/projects/nemotron_evals_research/users/baiheh/nano-rl/agent-teacher-pipelines`
  on 2026-10-16), plus runtime, vendor, tool and credential-file records (key names only).

  compares against its copy, `... capture` against `deepswe_capture.py`'s). `hengyuf-changes.diff` = 3 comment lines +
  `diff -ru a/scripts b/scripts`, a = Baihe's `scripts/*.py`, b = this app's (applies with `patch -p1` in a copy of
  Baihe's app).
* Campaign `source/` snapshots frozen before item 6 below list Baihe's `deepswe_capture.py` (sha256 `b1babe29...`);
  synth legs stage this live app (`S/synth/probe_worker.py`), so their later legs run item 6 all the same.
* `vendor/Gym.tar`: `git archive` of Gym `2f11dec3a1c11c0c5f302ab199f97754f7b5c8bd` (pax comment = commit; sha256 in
  `vendor/Gym.tar.sha256`, origin in `vendor/Gym.tar.provenance`).

## Differences from Baihe's ATP

Code (4 scripts: `deepswe_stage.py`, `deepswe_http.py`, `run_deepswe.py`, `deepswe_capture.py`; +75/-17 lines; see
`hengyuf-changes.diff`). Hosted model specs (no extra keys) get exactly Baihe's configuration; checked by
`tools/check_hengyuf_changes.py config` (kimi/glm `gym.yaml`, `gym eval run` command and launch environment
identical to Baihe's apart from ports and launch paths). Item 6 (how OpenCode's output reaches Lustre) applies to
every model and changes no configuration or artifact format.

1. `deepswe_stage.build_config`: per-model overrides from the model spec, else the globals: `policy_base_url` =
   `spec.base_url`, `policy_api_key` = `spec.api_key` (literal, e.g. `EMPTY`; default `${oc.env:NVIDIA_API_KEY}`),
   vllm_model `chat_template_kwargs` = `spec.chat_template_kwargs`, `sampling_overrides.max_tokens` =
   `spec.max_output_tokens`, OpenCode `opencode_max_context_window` = `spec.context_window`. A spec with
   `"local": true` also gets vllm_model `preserve_reasoning_in_assistant_content: true` and
   `sequential_reasoning_allowed: false`, the model-server settings of hengyuf's DeepSWE eval
   (`swe-rl-v2-sc-migration/eval/deepswe-v1.1/gym/plugin/configs/deepswe_eval/deepswe_eval.yaml`): history thinking
   is rendered as `<think>R</think>C` in the assistant content, exactly as in sc14's target rollouts. Gym's defaults
   would move it to `reasoning`/`reasoning_content` and the chat template would re-render it as `<think>\nR</think>C`
   (+1 token per reasoning turn). The newline form is what the model generated; parity with the eval targets was
   chosen.
2. `deepswe_stage.stage`: the staging config (`gym env prefetch` / `gym eval prepare`, which never call a model) omits
   per-model `base_url`/`api_key`. Otherwise a campaign source whose settings contain only the local student fails to
   stage when `SYNTH_STUDENT_BASE_URL` is unset (`gym env prefetch` resolves every interpolation). Frozen sources sort
   model aliases, so "first model" is alphabetical.
3. `deepswe_http.request_with_retry`: a call is hosted only if its URL equals `ATP_DEEPSWE_POLICY_BASE_URL +
   "/chat/completions"`, whatever the credential count (Baihe's code did this only with a two-key `.api`; with one
   key every non-internal `/chat/completions` call was hosted and would have received the NVIDIA key). Hosted calls
   bind the credential and use the shared `rate-limits/nvidia-api.json` cooldown and gateway-capacity retries, as
   before. Non-hosted calls (the local student) keep their own `Authorization` (`Bearer EMPTY`), honour only the
   model-scoped cooldown (`rate-limits/nvidia-api-<alias>.json`) and are never classified as gateway capacity.
   `canonicalize_reasoning` still applies to every payload. A chat call with no configured hosted endpoint is
   refused.
4. (Reverted 2026-10-16 19:20 for teacher parity.) An earlier version added `ClientConnectorError`, `Cannot connect
   to host` and `ClientPayloadError` to `deepswe_campaign.infrastructure_error`; those markers also reclassified kimi's
   hub connection errors, so `deepswe_campaign.py` is Baihe's again. A lost connection to the in-job student router
   therefore ends the slot as `needs_review` (excluded as infra), exactly like any unexplained transport error.
5. `run_deepswe`: the launch environment's `ATP_DEEPSWE_MAX_OUTPUT_TOKENS` (OpenCode `limit.output`, read by the
   capture overlay) is per model (`spec.max_output_tokens`, else the global); `gym eval run --temperature/--top-p/
   --max-output-tokens` record the model's effective sampling (same expression as the pinned `sampling_overrides`).
   `ATP_DEEPSWE_POLICY_BASE_URL` stays the hosted `settings["base_url"]` for every launch (set by `stage()`).
6. (2026-11-08) `deepswe_capture.run_opencode` writes + fsyncs each OpenCode output chunk to `stdout.log`/`stderr.log`
   in its own thread pool (`_STREAM_IO`), not on the Gym agent's event loop, where stalled Lustre fsyncs made aiohttp
   close every PTY of the process (2026-11-07: SandboxPtyError in 330 of 748 `sft/glm-rollouts-sftv3-20261107` slots;
   its staged-copy `capture_patch.py`, upstreamed here, cut drops from 0.77 to 0.014 per session-hour). Same bytes,
   order and per-chunk fsync; the next read and the file close wait for the write, also when cancelled; errors
   propagate as before. The 15 s post-interruption drain wait can now expire between chunks. Check: `... capture`.

No settings or manifest validation rejected the extra spec keys (`local`, `base_url`, `api_key`, `context_window`,
`max_output_tokens`, `chat_template_kwargs`, `checkpoint`) or the alias `sc14`, so none was changed. Of these, only
`checkpoint` is informational; `local` selects item 1's reasoning settings. Non-code:
own credentials (`.env`), no `.api`, vendor and runtime rebuilt here, `tools/` added.

Local student spec (contract SETTINGS, e.g. `S/synth/settings.json`):
```json
"sc14": {"id": "policy", "local": true, "base_url": "${oc.env:SYNTH_STUDENT_BASE_URL}", "api_key": "EMPTY",
         "context_window": 262144, "max_output_tokens": 131072,
         "chat_template_kwargs": {"enable_thinking": true, "truncate_history_thinking": false},
         "sampling_overrides": {"temperature": 1.0, "top_p": 1.0}, "checkpoint": "..."}
```
`SYNTH_STUDENT_BASE_URL` must be in `staged["env"]`: Gym runs with an environment built from `staged["env"]`
only. Set it before `stage()` (which copies `os.environ`) or add it to `staged["env"]` explicitly. With
`"local": true` the student's history thinking travels inside the assistant content (item 1), so neither
`canonicalize_reasoning` nor the student router's `reasoning_content` -> `reasoning` rename has anything to rewrite.

## Rebuild

Run from a login or CPU node. Network access is needed (python-build-standalone, PyPI); no GPU.
```bash
A=/lustre/fsw/portfolios/nemotron/users/hengyuf/swe-task/atp
cp -p <uv 0.12.9 or newer> $A/runtime/bin/uv          # hengyuf's ~/.local/bin/uv 0.11.16 cannot install CPython 3.13.14
/usr/bin/python3 -I -B $A/tools/build_runtime.py vendor       # needs vendor/Gym absent (chmod -R u+w; rm -rf)
/usr/bin/python3 -I -B $A/tools/build_runtime.py controller   # needs runtime/controller and vendor/Gym-controller-src absent
/usr/bin/python3 -I -B $A/tools/build_runtime.py verify       # imports + runtime/controller.freeze.txt
python3 -I -B $A/../tools/make_secrets.py                      # writes .env and ../secrets/opensandbox.env; --check to verify
```

## Staging and running

`scripts/deepswe_stage.py` (`stage()`) refuses to run outside a CPU Slurm allocation: it requires `SLURM_JOB_ID` and
`SLURM_JOB_PARTITION` starting with `cpu` (swe-task jobs use `cpu_datamover`). It also requires a job-local scratch
directory under `/tmp` or `/raid/scratch`. It copies `runtime/bin/uv` and `scripts/`, installs CPython 3.13.14,
extracts `vendor/Gym.tar` and applies all four overlays. It then builds its own scratch controller and server venvs
and fetches the pinned DeepSWE dataset plus the OpenCode 1.17.11 and ripgrep 15.1.0 releases. This takes about
1-3 minutes and prints `DeepSWE runtime ready: <scratch>/staged.json`.
```bash
/usr/bin/python3 -B $A/scripts/deepswe_stage.py --app $A --scratch /raid/scratch/atp-deepswe-$SLURM_JOB_ID
```
Offline checks (no model API calls, no sandboxes, no job submission):
```bash
$A/runtime/controller/bin/python -B $A/tools/check_hengyuf_changes.py http
<scratch>/controller/bin/python -B $A/tools/check_hengyuf_changes.py config --scratch <scratch>   # inside a CPU job
$A/runtime/controller/bin/python -B $A/tools/check_hengyuf_changes.py capture --scratch <private dir>   # ~20 s, item 6
```
