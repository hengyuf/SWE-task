# Backbone overlays

`opensandbox-tls.patch` backports Jonathan Li's proven OpenSandbox TLS option to
Gym commit `2f11dec3a1c11c0c5f302ab199f97754f7b5c8bd`. Verification defaults to
**true**; an explicit per-service setting is required to disable it. SDK HTTP
transports, PTY sockets, and this application's sandbox cleanup use the same setting.

`opensandbox-tls.metadata.json` records the source reference and exact base, patch,
and patched-file hashes. Preparation checks all hashes before applying the patch
to `vendor/Gym`, and evaluation verifies the resulting file again.

Keep future Gym or NeMo-RL fixes here as patches against an explicit commit.
Apply them only to `agent-teacher-pipelines/vendor`; never patch the shared
`nano-rl/pipeline` checkout. Configuration is generated by `scripts/atp_runtime.py`
into each application's run directory.

## Serving SDK overlay

`serving-requirements.txt` pins OpenAI 2.44.0 for the existing x86 NeMo-RL image's
vLLM 0.25.1 worker. Its baked OpenAI 2.6.1 lacks `NamespaceTool`, which prevents
the vLLM API server from importing. Only this pure-Python SDK and its distribution
metadata are overlaid; the image's compiled dependencies and source remain unchanged.

`check_serving_cpu.sbatch` stages that package into the generated `serving-python/`
directory and builds `serving-openai-2.44.0.zip`. It verifies API-server imports
inside the selected image without a GPU. It also checks CLI help, recording the
known device-detection limitation when this GPU build cannot construct its parser
on CPU; actual CLI execution remains part of the GPU smoke. The ZIP hash and image
identity are recorded in `runtime/serving-check.json`. GPU jobs verify that hash,
mount the ZIP read-only, and set `PYTHONPATH` to that single archive.
