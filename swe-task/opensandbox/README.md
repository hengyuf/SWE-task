This directory implements the sandbox operations needed by **DeepSWE Mid-train Synthetic Data.pdf** using the existing remote OpenSandbox Cell-3 service. The controller runs in a DFW CPU allocation. Repository commands execute inside a remote sandbox, and small receipts and exported artifacts return to the controller.

## What each kind of state means

An **image** is the starting filesystem and installed software named by a container registry reference. A **sandbox** is one running instance created from an image. A **snapshot** is a service-managed filesystem checkpoint that can create another sandbox. An **archive backup** is a downloaded copy of a selected workspace directory, with a manifest and supporting evidence.

Use an existing image for the first sandbox, install or upload the repository's prerequisites, then take a snapshot after preparation succeeds. Each task can start from that prepared state. Archive backups are useful for inspection and portable workspace transfer. Publishing an OCI image, which can be pulled from a registry by another service, is a separate optional operation.

Neither a filesystem snapshot nor a workspace archive is a promise to resume running processes, sockets, or in-memory state. Stop writers before capturing a reproducible checkpoint. For SQLite, make a consistent backup through SQLite's backup API before archiving its output.

## Connection and credentials

The helper reads `OPENSANDBOX_DOMAIN`, `OPENSANDBOX_API_KEY`, `OPENSANDBOX_TLS_VERIFY`, and `OPENSANDBOX_USE_SERVER_PROXY` from `$OS_ENV_FILE` (the default `--env-file`) as data. Exported `OPENSANDBOX_*` variables override the file, so check for intentional overrides when switching services. Do not `source` that file, copy it into a task workspace, print its contents, or embed its API key in command arguments or image layers.

The deployed Cell-3 endpoint uses HTTPS with a self-signed certificate. The existing configuration explicitly selects `OPENSANDBOX_TLS_VERIFY=false` for this service. The helper also supplies the API-key header on server-proxied command and file requests. Supplying the SDK's lifecycle `api_key` alone did not authenticate those proxy requests in the live probe. Prefer a trusted service certificate or a configured CA when the service provides one.

The DFW CPU allocation hosts the client. It does not host the remote sandbox's CPUs or memory. Slurm's resource request and OpenSandbox's resource request are independent, and sandbox capacity is shared with other workloads.

## Create, inspect, and run commands

Define this shell convenience function in the CPU allocation. It calls the Python helper; it is not an installed OpenShell or OpenSandbox CLI.

```bash
osb() {
  "$OS_PYTHON" "$OS_SCRATCH/helper/sandbox_helpers.py" \
    --env-file "$OS_ENV_FILE" "$@"
}
export OS_IMAGE=public.ecr.aws/d3j8x8q7/swe-bench-202605:kh75679ajj3b8dtd7se3h7z0a1833y6r-v1.1
export OS_RUN_TAG="deepswe-${SLURM_JOB_ID}-$(date -u +%Y%m%dT%H%M%SZ)-${RANDOM}"

osb create --image "$OS_IMAGE" --ttl 3600 --timeout 300 --network allow \
  --resource cpu=2 --resource memory=8Gi \
  --metadata purpose=deepswe-preparation --metadata "run=$OS_RUN_TAG" \
  > "$OS_SCRATCH/artifacts/create.json"
export OS_SANDBOX_ID
OS_SANDBOX_ID=$("$OS_PYTHON" -c \
  'import json,sys; print(json.load(open(sys.argv[1]))["id"])' \
  "$OS_SCRATCH/artifacts/create.json")

osb info "$OS_SANDBOX_ID"
osb exec "$OS_SANDBOX_ID" 'pwd; git rev-parse HEAD; git status --short' \
  --workdir /app --timeout 60
```

`--ttl` is the sandbox lifetime in seconds. It defaults to 600 seconds, so choose a longer lifetime for preparation or agent work. `--timeout` bounds a helper operation; increase it for cold image startup, long tests, or snapshot preparation. Expiration ends the remote workspace even if the DFW CPU job is still running. Conversely, ending the CPU allocation does not delete a remote sandbox immediately.

All commands except ordinary `exec` print JSON. Creation and snapshot commands report their object identifier in `id`. Ordinary `exec` emits the collected remote stdout and stderr when the call finishes and returns the remote exit code, so a failing test remains a failing shell command. `exec --json` returns a structured result for callers that need the streams as data. Use `--workdir` explicitly; otherwise the image's default directory applies.

```bash
# Illustrative exit-code check: this intentionally exits with status 7.
osb exec "$OS_SANDBOX_ID" 'printf "stdout example\n"; printf "stderr example\n" >&2; exit 7' \
  --workdir /app

# Extend the lifetime while work is still needed.
osb renew "$OS_SANDBOX_ID" --ttl 3600
```

An operation timeout returns exit code 124. For an executing command, the helper attempts to interrupt the execution ID it observed and reports `timed_out`, `interrupt_attempted`, `interrupted`, and the checked `remote_running` state when available. An accepted interrupt is not proof that every child process stopped. Inspect the owned sandbox before retrying a mutating command. If snapshot creation times out after receiving an ID, the error's `resource_id` lets you inspect or delete that snapshot. A lost create response can leave remote state uncertain; creation is not automatically retried.

If creation times out, use its unique metadata to inspect the outcome before submitting another create request:

```bash
osb find --metadata "run=$OS_RUN_TAG" --metadata purpose=deepswe-preparation \
  --page 1 --page-size 100 --timeout 60
```

`find` requires a metadata filter and returns one read-only page with `sandbox_infos` and `pagination`. Check `has_next_page` before assuming the result is complete. Inspect any returned ID with `info`; a request timeout is not evidence that no sandbox was created. The command never adopts or deletes a matching sandbox automatically.

New sandboxes default to `--network deny`, including those created with `restore-snapshot`. The example above explicitly uses `--network allow` for trusted preparation that may need dependency downloads. Create student task sandboxes with `--network deny`; Codex remains on DFW and communicates through the helper. If an agent inside the sandbox must call a model service, the benchmark's explicit model-host exception requires additional network-policy configuration beyond this simple allow/deny switch. The existing DeepSWE integration uploads OpenCode and ripgrep because their normal download paths fail under its restricted policy.

For a private image, pass `--registry-username-env NAME` and `--registry-password-env NAME` together to `create`. The named process environment variables supply the values. Keep registry credentials out of command arguments, task files, and exported build contexts.

## Upload edits and collect logs

`upload` and `download` transfer one file. To transfer a directory, use the workspace backup operations below. Local files belong in this helper directory or node-local scratch.

```bash
printf 'hello from the DFW controller\n' > "$OS_SCRATCH/artifacts/probe.txt"
osb upload "$OS_SANDBOX_ID" "$OS_SCRATCH/artifacts/probe.txt" /tmp/dfw-probe.txt
osb exec "$OS_SANDBOX_ID" 'cat /tmp/dfw-probe.txt' --workdir /app
osb download "$OS_SANDBOX_ID" /tmp/dfw-probe.txt "$OS_SCRATCH/artifacts/probe-returned.txt"
```

For a proposed source change, prepare a patch on the CPU node, upload it, and apply it in the remote checkout. The following assumes you have already prepared `change.patch` for the selected repository:

```bash
osb upload "$OS_SANDBOX_ID" "$OS_SCRATCH/artifacts/change.patch" /tmp/change.patch
osb exec "$OS_SANDBOX_ID" 'git apply --check /tmp/change.patch && git apply /tmp/change.patch' \
  --workdir /app --timeout 60
```

Run the repository's actual test command remotely. Preserve its exit status even when writing a log. For the selected Go task, a general test invocation is:

```bash
osb exec "$OS_SANDBOX_ID" \
  'go test ./... > /tmp/task-tests.log 2>&1; test_rc=$?; cat /tmp/task-tests.log; exit "$test_rc"' \
  --workdir /app --timeout 600
osb download "$OS_SANDBOX_ID" /tmp/task-tests.log "$OS_SCRATCH/artifacts/task-tests.log"
```

This command is a recipe, not a claim that a full task test suite was run during helper validation. Download the log after a failed test as well. In a script using `set -e`, explicitly capture the failure before the download so the script does not skip collecting evidence. Use `/tmp` or another remote directory for logs; a remote path is not a path on DFW Lustre.

## Save a workspace backup and restore it

The PDF's durable backup path is a selected-workspace archive plus enough provenance to understand and recreate its environment. Use this in addition to optional native snapshots.

```bash
osb backup "$OS_SANDBOX_ID" --workdir /app \
  --output-dir "$OS_SCRATCH/artifacts/prepared-A" --timeout 900
```

Choose a new or empty output directory. The output contains `workspace.tar.gz`, `manifest.json`, and, when supported by the workspace, `git.patch` and package listings. The manifest records unavailable Git/package queries instead of pretending their inventories are complete. The archive includes source files, untracked and binary files, executable modes, and Git history. Supported safe links are retained; unsafe archive paths, links escaping the workspace, and special files are rejected. Keep Dockerfiles, lockfiles, and explicit operating-system setup instructions in the workspace if they are needed to reproduce preparation. A package listing is evidence, not an installation script or a complete environment image.

The default path exclusions include `.env`, `.env.*`, `.codex`, `.ssh`, `.aws`, `.cache`, `__pycache__`, `.venv`, `venv`, `node_modules`, `.git-credentials`, `.netrc`, `.npmrc`, `.pypirc`, and `.git/config`. These exclusions do not scrub secrets committed into Git objects or credentials embedded in arbitrary source files. Review the backup before sharing it. A backup with the original implementation, plans, or tests belongs to the trusted preparation/verifier side of the workflow.

Create another sandbox from the same base image before testing restoration. Restore into a new empty directory first:

```bash
osb create --image "$OS_IMAGE" --ttl 3600 --timeout 300 \
  --metadata "run=$OS_RUN_TAG" --metadata purpose=archive-restore \
  > "$OS_SCRATCH/artifacts/restore-target.json"
export OS_RESTORE_ID
OS_RESTORE_ID=$("$OS_PYTHON" -c \
  'import json,sys; print(json.load(open(sys.argv[1]))["id"])' \
  "$OS_SCRATCH/artifacts/restore-target.json")
osb restore "$OS_RESTORE_ID" --backup-dir "$OS_SCRATCH/artifacts/prepared-A" \
  --destination /tmp/restored-app --timeout 900
osb exec "$OS_RESTORE_ID" 'git status --short; git rev-parse HEAD' \
  --workdir /tmp/restored-app
```

To restore over `/app`, explicitly add `--replace` and use only a sandbox you own and intend to replace. Replacement changes that destination's contents. Restoring a workspace does not reproduce packages installed under `/usr`, `/opt`, or another path outside the exported directory; reuse the same base image and replay the saved setup recipe where required.

## Take and restore a native snapshot

Native snapshots are a convenient way to reuse prepared filesystem state on the same service. They are optional acceleration for the workflow, not the only backup.

```bash
osb snapshot "$OS_SANDBOX_ID" --name prepared-A --timeout 600 \
  > "$OS_SCRATCH/artifacts/snapshot-A.json"
export OS_SNAPSHOT_ID
OS_SNAPSHOT_ID=$("$OS_PYTHON" -c \
  'import json,sys; print(json.load(open(sys.argv[1]))["id"])' \
  "$OS_SCRATCH/artifacts/snapshot-A.json")
osb snapshot-info "$OS_SNAPSHOT_ID"
osb restore-snapshot "$OS_SNAPSHOT_ID" --ttl 3600 --timeout 300 \
  --metadata "run=$OS_RUN_TAG" --metadata purpose=snapshot-restore \
  > "$OS_SCRATCH/artifacts/snapshot-clone.json"
export OS_CLONE_ID
OS_CLONE_ID=$("$OS_PYTHON" -c \
  'import json,sys; print(json.load(open(sys.argv[1]))["id"])' \
  "$OS_SCRATCH/artifacts/snapshot-clone.json")
osb exec "$OS_CLONE_ID" 'git rev-parse HEAD; git status --short' --workdir /app
```

Snapshot creation is asynchronous at the service. The helper's `snapshot` command polls until the service reports readiness or failure within the timeout. `restore-snapshot` creates a separate sandbox; it does not overwrite the original. Verify a deliberately saved marker as well as the repository commit before treating a preparation as reusable. The underlying SDK accepts either an image or a snapshot ID as its startup source, not both.

## Call the helpers from Python

Use the same CPU-local Python environment and imports for a small controller program. Save and run it beside the staged helper modules. The example creates one owned sandbox, inspects its repository, backs it up, and deletes that sandbox in `finally`.

```python
import asyncio
import os
from pathlib import Path

from sandbox_helpers import Client, Config
import workspace_ops


async def main():
    config = Config.load(Path(os.environ["OS_ENV_FILE"]))
    output = Path(os.environ["OS_SCRATCH"]) / "artifacts" / "library-backup"
    sandbox_id = None
    async with Client(config, timeout=300) as client:
        try:
            created = await client.create(
                image=os.environ["OS_IMAGE"], ttl=1200, network="deny",
                metadata={"run": os.environ["OS_RUN_TAG"], "purpose": "library-example"},
            )
            sandbox_id = created["id"]
            result = await client.exec(
                sandbox_id, "git status --short", cwd="/app", timeout=60,
            )
            if result.exit_code != 0:
                raise RuntimeError(f"Repository inspection failed: exit {result.exit_code}")
            print(result.stdout, end="")
            await workspace_ops.backup(client, sandbox_id, "/app", output)
        finally:
            if sandbox_id is not None:
                await client.delete(sandbox_id)


asyncio.run(main())
```

`exec` returns an `ExecResult`, including for a nonzero remote command status. Inspect `exit_code` and timeout fields; do not assume a returned object means the command succeeded. API/transport failures raise exceptions. Exiting `async with Client(...)` closes the local connection only; explicit `delete` controls remote lifetime. For an ambiguous create failure before the example receives its ID, recover through its metadata as described above.

| Additional library operation | Call inside the same async client context |
|---|---|
| Upload / download one file | `await client.upload(id, local_path, remote_path)` / `await client.download(id, remote_path, local_path)` |
| Ready snapshot | `await client.snapshot(id, name="prepared", wait=True, timeout=600)`; library `wait` defaults to `False`, unlike the CLI. |
| Snapshot restoration | `await client.restore_snapshot(snapshot_id, ttl=3600, timeout=300, network="deny")` |
| Inspect / renew | `await client.info(id)` / `await client.renew(id, 3600)` |
| Metadata recovery | `await client.find({"run": run_tag}, page=1, page_size=100)` |
| Snapshot inspection / deletion | `await client.snapshot_info(snapshot_id)` / `await client.delete_snapshot(snapshot_id)` |
| Archive restoration | `await workspace_ops.restore(client, id, backup_dir, "/tmp/restored-app")`; pass `replace=True` only for intentional replacement. |

## Apply the PDF's A → F workflow

The PDF's pages 3–5 describe a synthetic-task process. The helpers supply its filesystem and command operations. Repository understanding, task design, masking decisions, student rollouts, and instruction rewriting remain work for the agent/harness; this directory does not implement a complete synthetic-data pipeline.

| State or transition | What to do with these helpers | Keep on the trusted side |
|---|---|---|
| **A: prepared original repository** | Create from a compatible existing image, upload source/setup files, install dependencies with `exec`, run baseline tests, and save an archive backup. Optionally snapshot A. | Setup recipe, exact base commit, dependency evidence, original source. |
| **A → understanding and mask plan** | Read files and run inspection commands through `exec`; download `understanding.md` and `mask_plan.md` to the controller. Include `failure_analysis` when constructing the plan. | Plans and failure analysis can reveal the intended solution. |
| **A → B: masked working copy** | Clone A from a snapshot or restore its archive, apply the selected masking patch, and test the intended failure. Save the change as a patch before removing history. | Unmasked source, original Git history, and the masking patch. |
| **B → C: cleaned student state** | Remove solution-bearing Git history and caches from the owned candidate workspace, verify the remaining files, and create a fresh baseline Git repository if the grader needs `git diff`. Back up/snapshot the cleaned result. | Original backups, hidden tests, plans, and patches. |
| **Student rollouts on C** | Give the student only C and the task instruction. Run commands through its own sandbox; download logs and resulting patches. | Hidden verifier assets and reference solution. |
| **A + analysis + mask + rollouts → evolution plan** | Inspect the collected evidence and write `evolve_plan.md` on the trusted controller side. | Evolution rationale and solution-bearing evidence. |
| **Evolution → D → E** | Apply the evolution to a fresh owned workspace, preserve its diff, and validate D. Remove history/caches and other private artifacts to produce E, repeating the checks used for C. | D's private patches and planning materials. |
| **E → F: final instruction** | Rewrite the instruction against the tested student-visible E state. Export the final environment and collect verifier results before publishing F as a task. | Reference implementation, hidden tests, and grading-only files. |

Masking uses the same upload-and-`git apply` operations shown above. Save the original commit and a binary-capable patch before clearing Git history:

```bash
osb exec "$OS_SANDBOX_ID" \
  'git rev-parse HEAD > /tmp/pre-mask-commit.txt; git diff --binary > /tmp/mask.patch' \
  --workdir /app
osb download "$OS_SANDBOX_ID" /tmp/pre-mask-commit.txt "$OS_SCRATCH/artifacts/pre-mask-commit.txt"
osb download "$OS_SANDBOX_ID" /tmp/mask.patch "$OS_SCRATCH/artifacts/mask.patch"
```

`git diff` in that example captures uncommitted tracked changes; it does not capture untracked files or changes already committed after the chosen baseline. Use an explicit base revision when those changes matter, and keep the archive backup as well.

For the B → C or D → E cleanup step, `OS_MASKED_ID` must be the ID of a **separate owned candidate sandbox** whose masking/evolution is complete. Save its private archive and patches first. Download plans, hidden tests, and reference solutions to the trusted controller, then remove their exact remote paths from the candidate. The following clears only the named Git/cache paths and known temporary patch files; adapt the named private files to those actually produced by your task preparation:

```bash
# OS_MASKED_ID is the separate B or D candidate, never the original A sandbox.
osb backup "$OS_MASKED_ID" --workdir /app \
  --output-dir "$OS_SCRATCH/artifacts/private-before-cleanup" --timeout 900

# Run only after private patches/plans/tests have been downloaded and removed.
osb exec "$OS_MASKED_ID" \
  'set -eu
   test "$(pwd -P)" = /app
   rm -rf -- .git .cache __pycache__
   rm -f -- /tmp/change.patch /tmp/mask.patch /tmp/pre-mask-commit.txt
   git init -q
   git add -A
   git -c user.name="Task builder" -c user.email="task-builder@example.invalid" commit -qm "Student baseline"
   test "$(git rev-list --count HEAD)" = 1
   git log --oneline
   git status --short' --workdir /app --timeout 120
```

Inspect the resulting file list and the single baseline commit before student consumption. Confirm hidden tests, original implementations, planning documents, and reference solutions are absent wherever they were stored. A native snapshot captures filesystem state beyond `/app`, including private files left in `/tmp`; keeping the final repository clean alone is insufficient. Save trusted artifacts only on the controller, and checkpoint the cleaned candidate only after verifying those removals. This helper provides the explicit commands, not an automatic full anti-cheating audit.

The final Harbor-style task layout described in the PDF contains `task.toml`, `instruction.md`, `environment/`, `tests/`, and `solution/`. Keep hidden `test.patch` and fail-to-pass/pass-to-pass test IDs under the verifier's private `tests/` assets. Do not copy the whole task package, preparation archives, or reference `solution/` into the student image. The metadata and commands must agree with the final work directory, image, resources, and test runner. These helpers export workspace/build artifacts; they do not validate an entire Harbor task package.

## Export and optionally publish a portable image

For reuse on Cell-3, a validated native snapshot is often sufficient. To produce a registry image, export a reviewed workspace and an explicit base image into a build context. A **build context** is the directory containing the Dockerfile and files the image builder will consume.

```bash
osb export-build-context "$OS_SANDBOX_ID" --workdir /app \
  --output-dir "$OS_SCRATCH/artifacts/image-context" --base-image "$OS_IMAGE" --timeout 900
```

That example exports the prepared environment. For a final student task, substitute the verified cleaned C/E/F sandbox ID; do not export the original A workspace or a trusted preparation backup as the student environment.

If preparation installed dependencies outside `/app`, supply a reviewed, idempotent script with `--setup-script /path/on/controller/setup.sh`. The exported workspace and package evidence do not automatically convert the live container's entire filesystem into an image. Reproduce external changes using that script or choose a base image that already contains them. Pin a digest rather than a mutable tag when freezing a production task.

The generated Dockerfile replaces the selected workspace on the explicit base image, runs optional setup through `/bin/sh`, sets that workspace as `WORKDIR`, and uses root with a keepalive command. Review the recipe if your task requires a different user or startup behavior.
